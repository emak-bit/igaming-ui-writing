# Тексты для iGaming-агрегатора

## Маршрутизатор

1. Определи канал: сайт / письмо / уведомление.
2. Прочитай [voice.md](voice.md) и [glossary.md](glossary.md).
3. Если в тексте есть сумма, число, валюта, дата, процент или перевод на другую локаль — прочитай [numbers.md](numbers.md).
4. Прочитай **только** файл канала:
   - сайт, интерфейс, баннер, лендинг, карточка бренда, title/description/OG → [channel-site.md](channel-site.md)
   - письмо, email, рассылка → [channel-email.md](channel-email.md)
   - пуш и инбокс (всегда пара) → [channel-notifications.md](channel-notifications.md)
5. Если канал письмо или уведомление, перед финалом сверься с эталонами в [examples.md](examples.md).
6. Новый или спорный термин — дополни [glossary.md](glossary.md).

Если канал неясен — спроси одним вопросом. Не читай все три канала сразу.

## Эмоция по каналам

Общие правила «когда радуемся» — в [voice.md](voice.md). Градус берётся из этой таблицы, а не «на глаз».

| Канал | Эмоция | Первый приоритет | Восклицательный знак |
|---|---|---|---|
| Уведомление | минимум: факт и сумма | что случилось → что делать | нет |
| Сайт | спокойная польза | что изменится для меня | только в победе, один |
| Письмо | теплее: отношение + сразу факт | тема = суть; эмоция в открытии тела | в победе и промо-открытии, один |

Якоря:

- уведомление: «12 500 RUB уже на балансе»;
- сайт: «Выигрыш уже на балансе. Можно вывести»;
- письмо: «Есть победа! 12 500 RUB уже на балансе. Забирай».

Не усредняй тон между каналами. Письмо не пишет как пуш, пуш не празднует как письмо.

## Как работать над задачей

1. **Собери контекст.** Экран и элемент, что было до и что будет после, состояние (пусто, загрузка, ошибка, успех), кто пользователь (новый или играющий), ограничение по длине, есть ли переменные. Если речь про награду: тип (фиат / косточки / опыт) и куда садится (баланс / баланс бренда / бонусный счёт / профиль). Чего не хватает — спроси коротким списком, не выдумывай.
2. **Сформулируй задачу текста** одним предложением: что читатель должен понять и сделать.
3. **Напиши столько вариантов, сколько нужно.** Один текст: лейбл, плейсхолдер, ошибка ввода, статус операции, кнопка с очевидным действием. 2–3 разных подхода, не косметические перестановки: баннер, онбординг, тема письма, промо, страница, спорная формулировка.
4. **Дай рекомендацию**, если вариантов больше одного: объясни выбор в одну строку — какую задачу вариант решает лучше.
5. **Отметь риски**: двусмысленность, длина под элемент, склонение вокруг переменных, поведение при локализации, перепутанные места начисления, нужны ли данные от продукта или юриста.

### Формат ответа

Сначала задача текста. Дальше — блок своего канала. Поля письма не подмешивай в сайт и уведомление. Если вариант один — не нумеруй и не добавляй запасной ради запаса.

**Сайт и интерфейс**

```
Задача текста: [одно предложение]

Рекомендую: «...»
Почему: [одна строка]
```

Если вариантов несколько — Вариант A (рекомендую) / Вариант B, у каждого «Почему».

Для маркетинговой страницы, если просили страницу, а не один блок:

```
Title: «...»
Description: «...»
OG: «...»
```

**Уведомления**

```
Задача текста: [одно предложение]

Рекомендую:
Заголовок: «...»
Инбокс: «...»
Кнопка: «...»   # если по тапу есть действие
Почему: [одна строка]
```

**Письма**

```
Задача текста: [одно предложение]

Вариант A (рекомендую): «...»
Почему: [одна строка]
Кликабельность: открытия и клик по кнопке, оценка и одна строка почему

Вариант B: «...»
Почему: [одна строка]
Кликабельность: открытия и клик по кнопке, оценка и одна строка почему

Как ещё улучшить письмо
- [какой информации не хватает]
- [что сделать сильнее: тема, первый экран, оффер, кнопка]
- Полный вариант при полной информации:
  Допущения: [...]
  Тема / прехедер / заголовок / текст / кнопка
```

Когда правишь готовый текст, покажи «было / стало» и назови, какое правило нарушено. Если текст уже хороший, скажи это и не переписывай ради переписывания.
